# 小米算力平台\-OPS 上传模型功能文档

本文整理运营控制台「模型列表 → 上传模型」的完整提交流程，覆盖居中弹窗中的四段信息与提交后的校验链路，并对照推理引擎「编辑版本」弹窗说明版本锁定规则。截图处于空数据状态，表单显示的是各字段的默认值与提示文案，未包含校验失败与成功后的界面，相关分支以推断标注。

**一句话结论：**上传模型不是一次文件提交，而是把文件、模型元数据、推理配置、机型推荐四段信息组装成一份模型清单的过程。正因为清单是下游推理与客户端推荐的唯一依据，页面把大量字段设为必填，并在「已上架」后冻结其中不可变的参数。

# 交互载体与整体流程

上传模型采用弹窗，而非独立页面或侧滑面板。弹窗浮于模型列表之上，背后整页加遮罩但仍可辨认上下文；顶部标题栏居中显示「上传模型」，右上角仅一个关闭图标（X），没有分步指示；弹窗宽度按内容固定，截图中约占屏幕三分之一，高度受视口限制，内容超出时在弹窗内部纵向滚动并显示独立滚动条；底部操作区固定在弹窗底边，不随内容滚动，始终保持「取消」与「上传并校验」可见。与侧滑式面板相比，弹窗是阻断式模态：遮罩阻挡对列表页的任何操作，未提交即关闭会让已填内容全部丢失。

整体流程分四步：选择文件与目录（客户端即时计算 sha256）→ 填写模型信息 → 配置推理参数与推荐机型 → 提交后进入上传中、校验中，直至待上架。表单本身不产生中间保存，提交动作即开始传输。

# 文件段：上传对象与完整性

文件段位于弹窗顶部，是唯一非表单字段的区域，用虚线框表示可投放区域。

|要素|控件|规则|
|---|---|---|
|**投放区标题**|居中文字|「选择模型文件或整个目录」，明确支持两种粒度|
|**说明文案**|段落|可以选单个文件，也可以选整个模型目录；每个文件都会先算完整份 sha256，再上传；较大的文件会分片上传|
|**选择文件**|文字链|唤起系统文件选择器，单选或多选文件|
|**选择目录**|文字链|唤起目录选择器，整个目录作为一次上传对象|

三条规则分别对应三种工程保障：完整份 sha256 保证内容可校验，与列表页「上传前在浏览器计算 sha256」的提示一致；分片上传解决大文件在弱网下的失败重传问题；目录模式则对应真实模型的多文件结构，避免用户手工逐个选择。

# 字段依赖与联动规则

这一段的价值在于把散落的提示串成可实现的约束，也是研发评审时最容易产生歧义的部分。

|依赖关系|表现|实现含义|
|---|---|---|
|**客户端最低版本 → 引擎最低版本**|客户端最低版本未选时，引擎最低版本为禁用态并显示「先选择客户端最低版本」|引擎包的可选范围由客户端版本过滤：只列已上架、且最低客户端版本不高于当前选择的包，避免选出客户端无法加载的引擎|
|**推理引擎 → 文件格式**|文件格式直接显示「由推理平台决定」|格式由引擎的协议与清单决定，不由用户填写，减少非法组合|
|**版本号 → 同名版本序列**|新版本必须高于已有版本|提交前需比对同名模型的历史版本，阻止降版与重复版本|
|**推理强度范围 → 推荐推理强度**|推荐值默认为「自动」|推荐档应落在范围集合内，范围未包含的档位不宜作为推荐值|
|**推荐机型 → 客户端设备匹配**|按配置向当前设备推荐已上架模型|推荐机型的配置需与设备实际硬件比对，同一模型内只允许一个默认勾选|
|**上下文长度等清单参数 → 已上架锁定**|提示「已上架后不能改」|这些值写入模型清单并随包分发，变更必须走新版本，不能在上架后原地编辑|

# 提交与校验链路

底部固定操作区由「取消」与「上传并校验」组成，后者是橙色主按钮，也是表单唯一的提交出口。按钮文案直接点明提交后不是立即生效，而是先进入校验。

提交后的链路与列表页状态链一致：**上传中**（分片传输，客户端已算出完整 sha256）→ **校验中**（服务端核对对象大小与文件头，此阶段可终止或删除）→ **待上架** → **已上架**，失败则进入异常终态。因此表单里的必填校验只是第一道关，真正决定能否上架的是服务端的文件级校验与后续的上架动作。

另一处可借鉴的机制是引擎列表的校验说明：选择安装包时先读取压缩包大小与入口并计算 sha256，上传后的校验只核对对象大小，读取压缩包末尾目录确认入口，不下载整个安装包。这种"只读元信息"的校验方式把校验成本从 GB 级降到 KB 级，模型侧同样值得复用。

# 设计观察与待确认项

从表单工程角度看，字段定义与约束已相当完整，主要问题集中在长表单的可用性与少数规则表达上。

- **必填密度高、缺少分段导航**：模型段与推理段合计 22 个字段、18 个必填，全部平铺在一个滚动弹窗里。建议按「文件、基础信息、运行配置、机型」做分组锚点或分步，避免用户在中途丢失上下文。

- **推理强度范围存在语义冲突**：截图中「关」与「自动」同时被勾选。关表示不启用推理强度档位，自动表示由平台择档，二者语义互斥，需明确为单选互斥或限定组合。

- **禁用态仍带必填标记**：引擎最低版本在未选客户端版本时既禁用又标红，用户容易误判为填写错误。可考虑保留提示语并弱化星号，或在依赖未满足时给出步骤顺序指引。

- **推荐机型的规则表述不直观**：「默认勾选在同一模型里只能有一个」属实现语言而非操作语言，用户难以理解该勾什么。

- **排序字段缺少约束说明**：默认 0，但未说明取值范围与大小含义，也未说明与标签分类的优先级关系。

- **无草稿保存**：22 个字段的长表单一旦误关弹窗即全部丢失，建议支持本地草稿或至少做关闭确认。

- **失败分支未见设计**：上传中断、校验不通过、版本号冲突这三种情况在截图中没有对应界面，需补充错误提示与回填策略。
