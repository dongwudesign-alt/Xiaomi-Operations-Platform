## 一、功能定位

「上架与下架」是审批模块下按**动作类型**划分的功能分支，承载对象发布（上架）与下线（下架）两类操作的审批与留痕。

功能边界：

- 只处理「上架」和「下架」两种动作，不覆盖对象的创建、删除、配置修改等其他变更。
- 作用于被管理的对象（模型、推理引擎），对象类型的完整范围以平台侧定义为准（推断：由左侧「模型」「推理引擎」两个业务模块提供对象）。
- 审批是**可选能力**，由配置项控制是否启用，不是强制流程。

## 二、审批开关机制

平台以**配置项**而非业务流程来控制审批是否生效，两个动作的开关相互独立：

| 配置项 | 控制动作 | 取值含义 |
|---|---|---|
| `MSTORE_APPROVAL_PUBLISH` | 上架审批 | 开启：上架需提交审批单；关闭：上架直接生效 |
| `MSTORE_APPROVAL_UNPUBLISH` | 下架审批 | 开启：下架需提交审批单；关闭：下架直接生效 |

功能规则：

1. **开关关闭时的行为**：操作人执行上架/下架，系统按原有路径**立即生效**，不生成审批单，审批列表不产生任何记录。
2. **开关开启时的行为**：操作转为提交审批单，对象状态在审批通过后才变更。
3. **两开关独立**：可只启用其中一个，例如仅下架需要审批、上架仍即时生效。
4. **与状态机解耦**：审批层不改动对象的可用状态机，开启审批无需变更状态机的状态定义与流转规则。
5. **动态生效**：开关变更后立即影响后续操作，不要求重启或重新部署业务逻辑（推断）。
6. **状态可见**：审批关闭时，系统向操作者与管理员明确告知"当前审批未开启、上架下架立即生效、此处不会产生单据"，以避免误判为无数据或功能异常。

## 三、审批单要素

审批单作为一次上架/下架动作的记录载体，含以下信息项：

| 要素 | 功能含义 | 备注 |
|---|---|---|
| 单号 | 审批单唯一标识 | 用于检索与追溯 |
| 对象 | 被审批的目标对象 | 需可定位到具体对象（推断：含名称与版本） |
| 动作 | 上架 / 下架 | 与对应开关一一匹配 |
| 状态 | 单据所处审批阶段 | 待审批 / 已通过 / 已驳回 |
| 申请人 | 发起本次动作的账号 | 用于权责追溯 |
| 时间 | 单据提交时间 | 用于时效统计与排序 |
| 操作 | 对单据的处置能力 | 通过、驳回等（推断） |

## 四、业务流程

**关闭态（当前状态）**

```
操作人执行上架/下架 → 校验权限 → 直接变更对象可用状态 → 完成（无单据）
```

**开启态（推断）**

```
操作人提交上架/下架 → 生成审批单（待审批）→ 审批人处置
        ├─ 通过 → 变更对象可用状态 → 生效
        └─ 驳回 → 单据关闭 → 对象状态保持不变
```
